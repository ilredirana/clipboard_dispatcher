# Clipboard Dispatcher 使用说明

Clipboard Dispatcher 用于在多台设备之间同步最新的剪贴板内容。服务端只在内存中保存一份最新内容，不保存剪贴板历史。

支持文本和 PNG、JPEG、WebP 图片。文件、文件夹和剪贴板历史不在当前版本范围内。

## 使用前确认

1. 确定一台运行服务端的设备。可使用 Windows 一体化程序，也可使用 Docker 部署到 NAS 或服务器。
2. 仅在局域网同步时，设备使用服务端的局域网地址即可。
3. iOS、Android 或异地 Windows 设备接入前，服务端必须具备可从外网访问的 HTTPS 地址。
4. 每台独立接入设备都要在管理页创建一条设备记录。设备名称必须唯一，并同时作为设备 ID。

## 运行服务端

### Windows 一体化程序

直接运行 `ClipboardDispatcher-<版本>-windows-x64.exe`。程序启动本机服务端和 Windows 剪贴板客户端，并在系统托盘显示图标。

首次运行时，从托盘打开管理页，完成“首次设置”，设置管理员 Token。此 Token 用于登录管理页和修改系统配置。

Windows 一体化模式会自动将本机作为同步设备使用：

1. 本机设备名称使用 Windows 计算机名称。
2. 本机同步使用管理员 Token。
3. 无需在“同步设备”中再创建本机 Windows 设备。

退出程序时，在托盘菜单选择“退出”。配置保存于 `EXE文件目录\config.json`。

### Docker 源码包

将 `ClipboardDispatcher-<版本>-docker-source` 整个目录复制到 NAS 或服务器，在该目录执行：

```bash
docker compose up -d
```

首次启动会在 `data/config.json` 生成管理员 Token 和运行配置。浏览器访问 `http://<服务器地址>:9888`，使用 `data/config.json` 内的 `server.auth_token` 登录。

源码包直接运行 `python:3.11-slim`，不使用 Dockerfile。整个 `src` 目录会以只读方式挂载到容器，其中包含应用代码和 Tasker 资源。首次启动时，容器会安装 `requirements-server.txt` 中的 Python 依赖。

修改 Python、页面或 Tasker 文件后，在同一目录执行：

```bash
docker compose restart
```

修改 `requirements-server.txt` 后执行同一命令，容器会重新安装依赖。Dockerfile 仅用于构建镜像部署包。

依赖只保留在容器内。删除或重建容器后，下次启动会再次安装依赖。

### Docker 镜像包

将 `ClipboardDispatcher-<版本>-docker-image` 整个目录复制到目标设备，在该目录依次执行：

```bash
docker load -i clipboard-dispatcher-<版本>.tar
docker compose up -d
```

镜像导入只需执行一次。管理员 Token、数据和日志均位于 `data` 目录。

### Docker 日常维护

```bash
docker compose ps
docker compose logs -f
docker compose down
```

`docker compose down` 只停止和移除容器，`data` 目录会保留。删除 `data` 会清除管理员 Token、设备记录和运行配置。

## 首次登录与运行总览

Windows 一体化程序首次启动会进入“首次设置”。Docker 首次启动已自动完成初始化，直接进入登录页即可。

登录后，首页“运行总览”显示：

| 区域 | 含义 |
| --- | --- |
| 服务状态 | 服务端是否已启用 |
| 运行方式 | Windows 一体化、Docker 容器、服务端模式或仅客户端 |
| 跨设备同步 | 本次程序启动后，内容从一台设备上传并被另一台设备下载的次数 |
| 在线连接 | 正在等待同步通知的 SSE 连接数 |
| 服务端口 | 当前服务监听端口 |
| 程序版本 | 当前运行版本 |
| 最近同步 | 最近发生的上传和下载，以及内容类型 |

同一设备上传后再下载不计入“跨设备同步”。页面每 5 秒自动刷新一次。

## 系统配置

进入“系统配置”可以调整服务和同步行为。

### 服务与同步限制

| 配置项 | 用途 |
| --- | --- |
| 公开服务地址 | 为手机、Android 和远程 Windows 设备生成接入配置时使用的地址 |
| 数据 TTL | 最新剪贴板内容在内存中的有效时间。到期后下载返回空内容 |
| 最大上传字节 | 文本请求允许的最大体积 |
| 图片同步 | 控制是否允许同步图片 |
| 图片大小上限 | 单张图片允许的最大字节数，默认 5242880 字节，即 5 MB；分辨率上限为 4 亿像素 |
| 更新管理员 Token | 替换管理页登录凭据 |

公网使用时，在“公开服务地址”填写完整 HTTPS 地址，例如 `https://clipboard.example.com`，保存后点击“检测公开地址”。检测成功后再创建移动设备配置。

Docker 容器内部固定监听 `0.0.0.0:8000`，对外端口由 Compose 映射，默认是 `9888`。Windows 环境修改监听地址或端口后，需要重启程序生效。

反向代理配置见 [HTTPS 反向代理部署](reverse-proxy.zh-CN.md)。

### Windows 同步行为

Windows 一体化模式无需填写远程服务地址、设备 Token 或设备名称。

若 Windows 程序仅作为客户端使用，按以下步骤配置：

1. 在“服务与同步限制”关闭“启用服务端”，保存并重启程序。
2. 在服务端的“同步设备”创建 Windows 设备。
3. 打开该设备的“查看当前配置”，下载 `clipboard-dispatcher-windows-config.json`。
4. 回到客户端“系统配置”的“同步行为”，导入该 JSON 文件。
5. 按需要开启自动上传、自动下载、忽略空内容，并设置防抖延迟。

自动上传监听本机剪贴板变化。自动下载使用 SSE 接收其他设备上传后的通知并读取最新内容。

## 同步设备管理

进入“同步设备”，填写设备名称，选择 Windows、iOS 或 Android，然后点击“创建设备”。创建完成后，该设备行会显示“查看当前配置”和“更多”。

### 查看当前配置

“查看当前配置”始终读取设备当前凭据和当前服务地址：

| 平台 | 页面提供的内容 |
| --- | --- |
| Windows | 服务地址、设备名称、同步 Token、JSON 配置下载 |
| iOS | 四个快捷指令下载二维码，以及设备配置二维码 |
| Android | 已注入配置的 Tasker 完整项目、上传任务、下载任务及二维码 |

设备 Token 以明文保存在服务端配置中，管理员登录后可随时查看和下载。设备 Token 只能调用剪贴板同步接口，不能登录管理页。

### 更多操作

| 操作 | 结果 |
| --- | --- |
| 重新签发 Token | 生成新 Token，旧配置立即失效；重新下载或导入目标设备的配置 |
| 重命名设备 | 同时修改设备名称和设备 ID；重新下载或导入目标设备的配置 |
| 禁用设备 | 该设备立即无法上传、下载和订阅同步通知；配置仍可查看 |
| 启用设备 | 恢复该设备现有 Token 的同步权限 |
| 删除设备 | 删除设备和凭据；设备配置及 Android 下载链接立即失效 |

## iOS 设备接入

iOS 通过四个快捷指令完成配置、上传、下载和截图上传。iOS 端不能后台持续监听剪贴板变化，因此日常同步通过辅助功能的轻点背面触发。

接入前，服务端必须已配置可访问的 HTTPS 公开服务地址。

1. 在“同步设备”创建 iOS 设备。
2. 点击该设备的“查看当前配置”。
3. 用 iPhone 相机扫描“安装配置导入快捷指令”“上传剪贴板快捷指令”“截图自动上传快捷指令”“下载剪贴板快捷指令”四个二维码，并分别添加到“快捷指令”App。
4. 在 iPhone 上运行一次“CD:扫码导入配置”快捷指令，按其提示扫描页面中“设备配置”的第五个二维码。
5. 快捷指令会将二维码中的配置原样写入 iCloud Drive 的 `ClipboardDispatcher/config.txt`。完成导入后再使用上传、下载和截图快捷指令。
6. 首次运行时，根据系统提示允许相机、剪贴板、网络和 iCloud Drive 权限。

### 设置轻点背面

在 iPhone 中进入“设置”→“辅助功能”→“触控”→“轻点背面”：

1. 将“轻点两下”指定为“CD:下载剪贴板”快捷指令。
2. 将“轻点三下”指定为“CD:上传剪贴板”快捷指令。

下载快捷指令会读取服务端当前最新内容并写入 iPhone 剪贴板。上传快捷指令会将 iPhone 当前剪贴板发送到服务端。

重新签发 Token 或重命名 iOS 设备后，重新执行“配置导入快捷指令”并扫描新的设备配置二维码。

### 截图自动上传

安装“截图自动上传快捷指令”后，在“快捷指令”App 的“自动化”中创建“截屏”自动化，并将动作为运行“截图自动上传”。首次执行时按系统提示授予照片、网络和 iCloud Drive 权限。

## Android Tasker 接入

Android 使用 Tasker 执行自动上传和手动下载。图片同步需要 Tasker 5.15.12 或更高版本。

1. 安装 Tasker，并按系统提示授予剪贴板访问权限。
2. 在“同步设备”创建 Android 设备，打开“查看当前配置”。
3. 使用“完整 Tasker 项目”的下载按钮或二维码导入 `Clipboard Dispatcher.prj.xml`。
4. 在 Tasker 底部的“项目”页长按，选择“导入项目”，选中下载的 XML 文件。
5. 确认项目中的“剪贴板变化”Profile 已启用。

完整项目已写入服务地址和设备 Token，不需要创建或编辑 Tasker 全局变量。

项目包含以下内容：

| 项目项 | 行为 |
| --- | --- |
| Upload Clipboard | 自动识别并上传文本或图片 |
| Download Clipboard | 下载最新文本或图片并写入系统剪贴板 |
| 剪贴板变化 Profile | 剪贴板变化后触发 Upload Clipboard |
| 小米专属：敲击背板下载 | 使用 `dbtap_v2  Non-wakeup - Xiaomi.dbtap` 传感器触发 Download Clipboard |

下载图片时，Tasker 会将当前图片写入 `Tasker/.clipboard_dispatcher/cache/` 后设置到系统剪贴板。该目录带有 `.nomedia` 文件，图片不会进入系统图库。

重新签发 Token 或重命名 Android 设备后，从管理页重新下载并覆盖导入完整项目。稳定下载链接保持不变，每次下载都会注入该设备当前 Token。

只需要单个任务时，可在“只导入单个任务”区域下载上传或下载 XML；单任务不包含自动上传 Profile。

## 日常使用

1. 在任意已启用设备复制文本或图片。
2. Windows 自动上传开启时会自动发送。
3. Android 在剪贴板变化后由 Tasker 自动发送。
4. iOS 使用轻点三下运行上传快捷指令。
5. 在目标设备下载或自动接收最新内容。iOS 使用轻点两下，Android 运行 Download Clipboard，Windows 自动下载开启时自动处理。

服务端只保留最后一次成功上传的内容。新的上传会直接替换旧内容。

## 常见问题

### 管理页无法登录

确认输入的是管理员 Token。Docker 部署从 `data/config.json` 读取 `server.auth_token`；Windows 一体化程序在首次设置时创建该 Token。

### 手机二维码中的地址不对

在“系统配置”填写正确的 HTTPS 公开服务地址，保存并运行公开地址检测，然后回到“同步设备”重新打开当前配置。二维码会使用新的地址生成。

### 远程设备无法同步

依次检查：

1. 设备是否处于启用状态。
2. 设备是否在重新签发 Token 或重命名后重新导入配置。
3. 公开服务地址是否为 HTTPS，且外网能访问 `<公开地址>/health`。
4. 反向代理是否允许图片上传，并关闭 SSE 响应缓冲。

### Android 不自动上传

确认 Tasker 的“剪贴板变化”Profile 已启用，并已获得剪贴板权限。手动运行 Upload Clipboard 后，查看 Tasker 弹出的结果以确定是权限、网络还是服务端限制问题。

### iOS 无法读取配置文件

先单独运行“配置导入快捷指令”，再次扫描设备配置二维码。确认 iCloud Drive 可用，并允许快捷指令访问 iCloud Drive。

### 图片上传或下载失败

确认服务端“图片同步”已开启，图片格式为 PNG、JPEG 或 WebP，且文件大小未超过“图片大小上限”。默认上限为 5242880 字节，即 5 MB；分辨率上限为 4 亿像素。

### 设备配置泄露或设备丢失

在该设备行的“更多”菜单中选择“重新签发 Token”或“禁用设备”。两项操作都会立即阻止旧 Token 继续同步。

## 备份与恢复

备份运行配置即可保留管理员 Token 和设备记录：

| 运行方式 | 备份位置 |
| --- | --- |
| Docker | 部署目录的 `data/config.json` |
| Windows 一体化程序 | EXE 同目录的 `config.json` |

恢复时，在程序停止后将备份文件覆盖回相同位置，再启动程序。
